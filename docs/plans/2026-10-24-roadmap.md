## Specs for U1–U8 (from the owner-approved draft, 2026-10-24)

### Context

The owner tested the Medications screen and the camera (2026-10-24) and asked for these changes:

1. **The Medications screen is too busy.** The Track tab holds everything in one long scroll: TODAY's doses, each
   schedule's phase line, supply warnings, symptoms, SCHEDULES and the medication list
   (`ui/MedicationToday.kt` `medicationTrackHeader`, called from `BodyTracker` page 0 in `ui/BodyScreen.kt:193`).
   It gets split into tabs.
2. **No ongoing doses.** A schedule is only fixed-length phases (`MedPhase.length` × `PhaseUnit`; `phaseOn` in
   `data/MedSchedules.kt:240` returns null once a non-repeating cycle has run out). Someone on a permanent daily
   medication has to fake it with a repeating one-day phase.
3. **Once a schedule is running you can't restart it or fix its start date.** `MedActivation.start` is set only by
   `activate`. The RUN section (`ui/ScheduleEditorScreen.kt:223`) only offers Pause/Resume and End.
4. **Camera alignment:** the last photo is shown at 30% opacity (`ui/CameraScreen.kt:304`). The owner wants a bold,
   highly visible white outline drawn over the translucent photo, so both show together.

**Owner principle (2026-10-24), for CLAUDE.md and memory:** FlexNotes is for any kind of user. No feature may lock
people into one pattern (for example cycles only). Every function must be easy to understand and use: plain wording,
sensible defaults, and every mistake fixable from the screen that shows it.

Owner choices (2026-10-24):
- Tabs: **Today · Schedules · Medications · History · Graph**.
- Outline: **body outline only**, using on-device ML Kit selfie segmentation with the model bundled in the app. It
  works offline, and any merged `INTERNET` permission is removed with `tools:node="remove"`.
- An opacity control and a line-thickness control on the camera, besides the on/off switch.
- The four gaps found while checking are filed as issues: as-needed (PRN) medications, tapering / step-up phases,
  a list of past runs, and a simple first-schedule setup.

### U1: tabs

  symptoms (`symptomRows`), with an empty state that points to Schedules. **Schedules:** each schedule's row and
  state, plus + New schedule. **Medications:** the list with latest values, the Reorder toggle and the extras.
  **History** and **Graph** stay as they are.
- Split `medicationTrackHeader` into `medicationTodayTab` and `medicationSchedulesTab`. Move the `ReorderToggle`
  page check to the Medications tab's index. The Body tracker is unchanged.
- The app opens on Today when anything is due today, otherwise on Medications. A reminder tap
  (`EXTRA_OPEN_MEDICATIONS`) opens Today.

### U2: ongoing
- Add `PhaseUnit.ONGOING` with a new unit code (check `PhaseUnit.of`'s fallback for unknown codes). It is stored in
  the existing `med_phase.unit` column, so there's **no database change**. `PhaseSheet` gets "Ongoing (no end)" next
  to days / weeks / months / years.
- Rules: only the last phase can be ongoing. "Repeat the cycle" is hidden while the last phase is ongoing. In
  `phaseOn`, an ongoing phase never ends (`last` null), and `phaseText` reads "On · day 40 · ongoing".
- Check every reader of `PhaseState.last` / length: `MedReminders.next`, `Supply.of` (it already walks a horizon),
  `EmergencyCard.current`, `MedicationReport`, `scheduleSummary` and `phaseLabel`.

## Specs for T1–T8: sessions, training load and energy (2026-10-26)

### Context

The owner supplied *Training Load & Energy Expenditure — Reference Specification* (session RPE, session load, ACWR,
MET calories, combat-sport METs, a data model and UX rules), saved as
`docs/reference/training-load-energy-expenditure.md`. FlexNotes already covers part of it, so these issues fill gaps
only:
- `data/Energy.kt`: MET calories (`netMetKcal`), `Effort.fromRpe`, `Activity` (16 Compendium activities, with only a
  generic `SPORTS` 6.0 and no combat sports), set by the exercise editor (#174).
- `data/TrainingLoad.kt` (#217): acute 7-day / chronic 28-day load from VOLUME or SETS, the ratio, `SPIKE` 1.5,
  `LOW` 0.8, Foster monotony and strain; shown in `ui/ReadinessTab.kt` and the day log's `ReadinessCard`.
- `SetRow`: `durationSec`, `rpe` (1–10, half steps), `metric`, `done`. There's a workout timer (`workout_time`).
  Custom exercise types (#14) hold up to 3 values. Routine days predefine sets (`routine_day_set`).
- The profile (`ui/ProfilePage.kt`, `PortableSettings.profile*`, #172) holds sex, date of birth (age per date via
  `Energy.age`), height and lifestyle; the TDEE, body fat and steps read it from there. Body weight is the logged
  bodyweight on the date.
- Missing: session RPE and session load, live/hard minutes, session type and intensity, a cardio zone, and a max heart
  rate in the profile.

### Owner decisions (2026-10-26)

- **A session is logged like any other entry**: no timed prompt or notification. It's a built-in **Session** exercise
  type, and each set is one session (duration, session RPE 0–10, hard/live minutes, intensity, session type, cardio
  zone, comment, done tick). It's added to a day like any exercise ("BJJ class", "Tennis games", or "Session RPE" at
  the end of a gym day, its duration filled from the workout timer and editable), it can be predefined in workouts,
  and it can be edited at any time.
- **The cardio zone is recorded by the user** (Zone 1–5), stored for the record and used where a calculation needs
  intensity. A small, on-demand ⓘ sheet explains the zones (effort and talk test, plus the user's own bpm ranges from
  their age if the profile has it).
- **Profile data is used, never asked for again** (owner, 2026-10-26): any function needing fixed facts about the
  person (age, sex, height, max heart rate) reads the profile. Anything missing is added to the profile so the user
  records it once (here: Max heart rate, in #241). Changing values like body weight come from the body tracker.
- **Heart rate from Health Connect is left out** (average/max HR, zones and recovery duplicate the wearable's app).
- In: combat and other sports in the Activity list with intensity, a Rounds type, session type, training load
  (session load, ratio bands, spike warning, internal vs external), and gross and net calories.
- Ruled out (recorded in the reference doc): wearable imports beyond Health Connect (local-only rule), team-sport GPS
  metrics (custom types cover anything counted by hand), a timed RPE prompt.
